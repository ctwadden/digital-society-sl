# Connect the Clinic: contributor instructions

## Scope and authority

This directory belongs to the original educational game. Preserve other material in the containing repository. Read the teacher's latest direction in `docs/CLAUDE_CODE_HANDOFF.md` and the active task packet. Historical reports describe their recorded versions; they are not permission to restore superseded behavior.

The requested team has Claude Code as department head and Codex as specialist workers. Claude owns the shared contract, integration and release. A Codex worker must read `docs/claude-codex-team/WORKER_CONTRACT.md` and its named brief under `docs/claude-codex-team/jobs/`.

## Working rules

- Work only within the exact editable paths assigned in the active packet. Proposed ownership in a role brief is not an active assignment. Request a contract/file handoff from the lead when needed.
- Do not spawn further workers, change provider/authentication/billing, install orchestration services, or publish from a specialist task. Return findings and artifacts to Claude.
- Keep one authoritative state and stable action/device/port/visit/asset IDs. Interface and narrative display derived results; they cannot independently award success, money or truck eligibility.
- Separate mentor demonstration, learner practice, changed-situation evidence and teacher judgement. Preserve learner explanations verbatim. No invented curriculum codes or automatic IB grades.
- Make original assets and code. Use historical Aspire analysis for general design observations, not proprietary code, art, dialogue or maps.
- Keep apprenticeship teaching, hints and retries free; reading is untimed. Keep keyboard alternatives, visible focus and reduced-motion support.
- Preserve valid historical progress and recovery behavior. Reject damaged imports without overwriting valid current work. No student accounts, names or patient information.
- Use existing authorized development tools and subscription sessions. Do not add paid API use, new subscriptions or runtime AI dependencies.
- Verify meaningful behavior. A screenshot, successful build or test count alone does not establish a complete game or school readiness.
- After an initial fix and one focused repair fail, report evidence, investigate the cause and change approach.

## Existing checks and entry

Run `npm test` from this directory. The current command explicitly enumerates test directories; newly introduced test directories must be registered by the lead. Serve the directory over HTTP and open `dist/opening-shift.html`; do not rely on `file://` module loading.

Each worker returns `complete`, `partial` or `blocked`, changed paths, observed checks, remaining gaps and integration instructions. Do not claim that a suggested command ran or that a provider/model was used without evidence.
