# Reusable delegated simulation team

These are the bounded jobs used for Opening Shift. Replace bracketed source paths and domain entities for another topic. Preserve the distinction between a causal model, its interface, and teacher judgement.

## Lead integrator — Delegate skill

Read the supplied lesson, existing project and saved-state contract before selecting a stack. Create one run record and shared contract with source versions, deliberate simplifications, stable IDs, worker-owned files and acceptance tests. Retain architecture, domain-rule decisions, assessment boundaries and final acceptance. Start at most two builders concurrently; reserve a fresh independent reviewer. Inspect real files and integrated behavior. Preserve existing work. After two failed fixes, investigate and change approach. Complete the authorized work and publish a review build only to the established destination; no new paid runtime service. Report what works, tests actually run, remaining uncertainty and the teacher/school pilot needed.

## Gameplay / simulation engineer — learning-simulation-engine

**Inputs:** `[shared contract]`, `[scenario]`, `[existing model]`, `[source limitations]`.

**Owned outputs:** `[model module]`, `[model tests]`, `[API contract]` only.

Implement one serializable authoritative state. Publish exact action payloads and derived views early. Make success depend on current causal conditions and actual learner evidence. Use stable entities, actions, faults and events. Distinguish setup, demonstrations, player actions and engine checks. Support more than one valid solution where the brief permits it. Reject actions/imports atomically; keep recovery, reset, refunds and payment safe. Do not infer understanding from money, speed or help. Test full valid paths, realistic failures and repairs, alternative solutions, stale observations and damaged saves. Return actual commands/results and limitations. Do not publish or edit UI files.

## Curriculum and content connections — learning-simulation-design

**Inputs:** `[teacher lesson/chapter sections]`, `[source ledger]`, `[scenario and engine API]`.

**Owned outputs:** `[student content module]`, `[learning/evidence notes]` only.

Turn the source into a client need, meaningful choices, concise I-can statements, graduated hints, human consequences and a short handover. Display two or three goals at a time. Keep taught examples distinct from independent evidence. Tie optional concepts and contexts to decisions the model actually permits; do not force extra quizzes into the game. Record supplied-source basis versus original extensions. Never invent official curriculum codes or map game currency to grades. Preserve the learner's own explanation and the teacher's judgement. Return exact exported content shapes and unresolved source alignment. No state/success logic or teacher answer sheet in the public bundle.

## Original graphics specialist — learning-simulation-interface

**Inputs:** `[scene anchors]`, `[stable asset IDs]`, `[actual view fields]`, `[visual direction]`.

**Owned outputs:** `[original assets]`, `[pure scene renderer]`, `[manifest entries]`, `[art review]` only.

Build an original, lightweight, recognizable workplace. Establish camera, scale, palette and object anchors; separate furniture from devices, connections and state overlays. Use model-provided link and test facts. A cable drawing is not proof of service. Keep critical status available as text and symbol as well as colour. Provide accessible companion labels and editable source. Inventory every asset/state with provenance and dimensions. Verify a representative asset in the actual scene before scaling. Do not copy reference-game maps, art, interface skin or code. No simulation or completion logic.

## Interface / game experience specialist — learning-simulation-interface

**Inputs:** `[API contract]`, `[content module]`, `[scene renderer]`, `[interaction acceptance]`.

**Owned outputs:** `[UI module]`, `[styles]` only.

Make the first decision obvious. Build the phone brief, scene selection, equipment/port controls, diagnostics, access decision and handover around one authoritative view. Dispatch actions; never independently declare success. Offer keyboard and non-drag alternatives, readable text, visible focus, clear failures, reduced motion and a stacked narrow layout. Preserve address/explanation drafts through rerenders and read-only conflicts, and distinguish drafts from accepted evidence. Render current versus stale player tests clearly. Guidance costs must be explicit before acceptance; practice, ordinary controls and accessibility are free. Verify the complete interaction, not merely component compilation.

## Independent QA — learning-simulation-qa

**Inputs:** `[shared contract]`, `[actual build]`, `[source alignment]`, `[test artifacts]`.

**Owned outputs:** `[independent tests]`, `[findings report]` only. Do not fix production code.

Try to break the complete mission. Test both valid solutions and each meaningful fault. Check whether repair truly restores service, whether obsolete tests can pass a changed system, and whether exports honestly record choices and explanations. Test damaged import, valid recovery, reset, refunds, repeated payment, tab ownership and lost drafts. Audit keyboard/focus, non-colour cues, readability, missing assets and likely school-device constraints. Separate automated, local browser, published-site and actual school observations; never mark an unperformed gate as passed. Give reproducible defects with severity, expected behavior and observed behavior. Recheck only concrete repairs or required gates.

## Handoff format for every worker

Return task/status, exact changed paths, behavior delivered, commands or inspections actually run, observed results, remaining gaps and integration notes. Use inherited authorized agents; model/effort/billing telemetry is unknown unless exposed. Budget one initial attempt and one focused repair. Escalate missing source, ownership/contract conflicts or repeated failure to the lead; do not create further agents or publish independently.

## Using this team for other topics

Retain client requests, inventory, guidance, evidence and recovery. Replace the domain model: hardware compatibility and boot checks; media editing/export constraints; legitimate and unauthorized security probes; or synthetic health-data collection and transfer. Write topic-specific causal tests first. A new client card or background alone does not create a new learning simulation.
