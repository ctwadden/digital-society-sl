# Codex job 07 — Independent QA and first-player review

## Assignment

You are the independent reviewer working for Claude Code. Try to disprove the integrated build's claims against **R1–R7**. Read `docs/claude-codex-team/WORKER_CONTRACT.md` and the task packet. Begin with raw requirements and the playable artifact, not a builder's reported conclusion. Do not repair production or weaken acceptance to obtain a pass.

## Skills

Read `learning-simulation-qa` when locally available. Use the common contract and this brief if absent, reporting the limitation. `delegate` supplies the evidence/reporting discipline; do not create another agent layer.

## Inputs

Use the corrected handoff, agreed contracts, supplied-source notes, exact tested revision, launch route, relevant legacy fixtures and available browser/test tools. Inspect actual artifacts. Obtain a runnable first slice before claiming gameplay findings. Missing tools produce explicit `not_tested` results.

## Owned outputs

Default to a read-only invocation returning findings for Claude to save. If the task explicitly grants writable paths, own only named reports under `qa/apprenticeship/` and named independent tests in registered test directories. No production, shared contracts, deployment or builder-test edits. A read-only role instruction alone is not a sandbox; obey the actual runtime controls and activated allowlist.

## Deliverable

Return reproducible, severity-ranked findings with expected/actual behavior, steps, exact revision/environment, evidence and recommended owner. For each check report `pass`, `fail`, `partial`, `blocked` or `not_tested` and its exact scope, then state overall `complete`, `partial` or `blocked`. A first-slice check cannot pass the entire apprenticeship requirement. Validate fixes at the affected boundary without endlessly widening the audit.

## Concrete checks

Play fresh and returning routes. Test valid and alternative equipment choices, wrong address/mask, unplugged path, wrong attempted repair, relevant repair and stale diagnostics. Check mentor advice, scene consequences and teacher export against real state. Try skipping dialogue, watching demonstrations, repeated reward actions and malformed imported progression to expose false truck eligibility.

Exercise save/reload, interrupted work, draft recovery, reset, corrupt/unsupported import, legacy saves, exports and competing tabs. Check keyboard-only and non-drag operation, focus, labels beyond colour, readable/reflowed text, reduced motion and missing assets. Record performance measurements only when actually measured.

Observe whether the opening explains role, purpose and next action; label enjoyment and beginner timing as unvalidated until a student pilot. Distinguish automated checks, preview browser, published site and actual managed school Windows/assistive technology. Never infer classroom readiness, academic mastery or IB grades from test count.

## Budget and result

One bounded review plus one targeted recheck after repair. Repeated failure goes to Claude with the cause and different investigation proposed. Return exact findings and untested areas; do not publish or claim unavailable tests ran.
