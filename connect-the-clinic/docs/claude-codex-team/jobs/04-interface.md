# Codex job 04 — Interface and player experience

## Assignment

You are the interface specialist working for Claude Code. Make the apprenticeship feel understandable and enjoyable through the playable scene and contextual controls. Satisfy **R1, R2, R4, R5 and R7**. Read `docs/claude-codex-team/WORKER_CONTRACT.md` and the exact task packet. Implement the assigned slice, not a replacement application.

## Skills

Read `learning-simulation-interface` when locally available. Use `delegate` for the bounded contract only. Missing local skills do not imply missing instructions: apply this brief and the common contract and report the limitation. Do not spawn other agents.

## Inputs

Read the corrected handoff, current entry/UI, programme action/view contract, gameplay beats, learning content and asset manifest. Confirm available browser tools and actual rendering environment. Obtain missing shared interfaces from Claude before depending on invented fields.

## Owned outputs

Proposed defaults: `dist/apprenticeship/ui.js`, `dist/apprenticeship/scene.js` and `dist/apprenticeship/styles.css`. Edit only activated paths. Claude retains entry HTML, `dist/opening/main.js`, programme integration and shared persistence unless explicitly reassigned. Art owns assets; coordinate requests instead of editing its files.

## Deliverable

Create the scene-first opening, contextual equipment/tool controls, device inspector, mentor/phone messages, diagnostics and clear next action. Keep the clinic, people and task visible. Open technical panels when useful. The tool bag and equipment should support real inspection/use, not decorative Continue steps.

Dispatch learner actions to the model and render returned state. Derive visible ports, connections, tests, staff consequences and truck availability from stable IDs. Clearly distinguish installed, powered, tested, failed and stale. Keep essential text in semantic HTML and support asset-failure fallback. Preserve drafts, caret, logical focus, dialog return focus and truthful read-only/save status.

## Concrete checks

Exercise arrival through one real task, a plausible error, diagnostic, advice and repair in the actual browser. Repeat essential operations with keyboard and non-drag controls. Check clear focus, readable text, labels beyond colour, reduced motion and a representative school-size viewport; inspect zoom/reflow where tools permit. Record exact environment and observations, not assumed accessibility compliance.

Confirm that closing a message, pressing Continue or watching a demonstration cannot award progress. Verify scene/test feedback remains truthful after changing the configuration and that returning progress reopens coherently. Screenshots must show the running game, not an unrelated concept mockup.

## Budget and result

One bounded implementation plus one focused repair. Investigate and change approach after a repeated failure. Return status, changed paths, actual interactions tested, screenshots/evidence paths, integration needs and untested areas. Do not publish or calculate independent success rules.
