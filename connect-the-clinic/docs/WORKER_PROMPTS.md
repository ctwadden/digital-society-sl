# Reusable worker assignments — first clinic build

> Public export: private source locators and former hosting metadata have been removed. Historical implementation records are retained for context; see the project-root MIGRATION.md and qa/EXPORT_TEST_RESULTS.md for this export. Some historical review files referenced below are intentionally not included.


These prompts were assigned after the teacher authorized development. The lead owns shared contracts and release decisions. All workers read `CONTRACT.md`, the two reviewed specifications in `contracts/`, the relevant source notes and acceptance matrix. Work is bounded to owned files; changes crossing a boundary are proposed to the lead. A worker's own test report does not replace independent QA.

## Lead integrator

Integrate one complete clinic and free bootcamp. Own `dist/main.js`, `dist/index.html`, `dist/persistence.js`, build/source/hosting configuration and release records. Preserve existing Teacher OS, Evidence Map and unrelated projects. Keep one authoritative state. Resolve schema differences, validate actual browser behaviour and preserve current student drafts in export. Verify hosting constraints without purchasing services or changing billing. Release a private teacher review version with an honest operating guide and school-pilot gate; no automatic classroom-ready claim.

## Simulation engineer

Own `dist/engine.js`, `dist/catalog.js`, `tests/simulation/`, `docs/ENGINE_API.md` and `docs/MODEL.md`. Implement pure validated actions, real graph/port/address/service/access evaluation, two equipment routes, inherited fault repair, immutable observations, marker collection/handoff/receipt, same-engine practice and the frozen consultation/delivery/payment ledger. Publish API shape early. Test working and broken paths, invalid actions, imports, early repair, stale results, reset/replay and idempotence. No DOM, presentation-only success, grades or remote service.

## Interface and accessibility designer

Own `dist/ui.js`, `dist/styles.css` and optional UI tests. Consume the engine's derived view and dispatch player actions. Build readable original 2D room and list modes, equipment controls, labelled non-drag wiring, inspector, diagnostics, phone, guide quotes and handover/export. Preserve focus and drafts; expose errors and current versus earlier results. All essential actions must work by keyboard; test narrow/reflow and reduced motion. Never calculate independent completion or silently fix a network.

## Mission designer

Own `dist/content/learning.js`, `docs/TEACHER_GUIDE.md` and `docs/SOURCE_ALIGNMENT.md`. Write original brief, four job roles, explanations, three free bootcamp stations, three guide sections with graduated hints, glossary, I-can statements and stakeholder consequences. Teach through explain/demonstrate/practice/changed example. No answer generation or fictional curriculum IDs. Price metadata is explanatory; engine quotes determine actual charges. Keep teacher-only worked paths out of the served student bundle.

## Art director

Own `dist/art.js`, `dist/assets/`, `asset-manifest.json` and `docs/ART_REVIEW.md`. Create/review original code-native vectors and a manifest with real source/provenance/hash. Keep 4/8-port switches, AP uplink, Ethernet adapter and sensor dock visually honest. State cues must come from engine-derived views and include text. Keep home collection separate from clinic radio coverage. Mark deferred/consolidated prior asset proposals explicitly. No copied Cisco art or branding and no separate success logic.

## Content connections reviewer

Own `docs/CONTENT_REVIEW.md`. Audit the implemented instructional content against supplied Computers lesson, Networks extract, security-layer slide and relevant textbook passages. Confirm every first-pilot connection changes an action, decision, consequence or explanation. Check Systems, Power and Values and ethics plus stakeholders; distinguish core content from later economics/media/routing candidates. Keep all official outcome codes unassigned until verified. Do not broaden the first build or change code to manufacture alignment.

## Independent QA

Own `tests/qa/` and `qa/`. Test the actual built source, independently of the feature authors. Try valid routes, broken links, bad/duplicate IPs, power/service/permission faults, early repair, stale results, sensor receipts, guide charging and settlement, malformed/imported saves, reset/replay, live draft export and accessible controls. Return concrete defects to owners; do not change production or lower expected outcomes. Record environment, commands/steps, expected/actual, fixes and not-run areas. Separate automated domain checks, cloud-browser observation, actual school Windows checks and student pilot. Stop repeating a failed fix after two attempts and investigate the cause.


## Revision 0.4 specialist assignments

Read `revisions/REVIEW_0_4.md` for the six-observation work order and `CONTRACT.md` for authority. These are bounded revisions to the existing clinic, not permission to replace its stack or create more missions.

- **Simulation engineer:** Use Learning Simulation Engineering. Own engine/catalog, simulation tests, model/API docs. Implement the unplugged-link transfer and retained reasoning, separate free full-clinic practice, engine-selected current goals, truthful site boundaries and strict save compatibility. Verify valid/failed/repaired routes and zero-earning practice before handoff.
- **Interface and visual specialist:** Use Learning Simulation Interface. Own UI/styles/art/manifest. Render current goal IDs and diagnostic paths from the engine, put home outside the clinic, expose ports and preserve drafts/focus across all state replacements. Include original asset provenance and test version labels. Coordinate fields before editing.
- **Learning and content reviewer:** Use Learning Simulation Design. Review supplied source extracts and actual decision/evidence opportunities. Own the review note only; lead applies copy. Provide current-goal groups, transfer prompt/hints, teacher practice language and pilot questions. Distinguish source review, contract walkthrough and actual gameplay.
- **Independent QA:** Use Learning Simulation QA with raw contract and build. Own tests/QA records only. Attack causal failure/repair, payment/practice, legacy saves, damaged import, reload/reset/multiple tabs and exact evidence. Report automated, browser, published and school checks separately. Do not repair production independently or infer a grade.
- **Lead integrator:** Use Delegate to assign ownership, resolve shared contracts, inspect actual behavior, integrate, preserve audience and publish the reviewed version. Keep the decision log, task list and release record current. Actual school testing and a small learner pilot remain separate gates.

For another subject, keep these ownership and acceptance patterns but replace the mission sources, causal model, choices, faults and human consequences. Reuse the workflow; do not merely relabel the clinic's network rules.

## Game experience and first-play roles — revision 0.5

Use `GAME_EXPERIENCE_ROLES.md` for the reusable lead, game/learning designer, interface/UX engineer, art specialist and independent-play-reviewer prompts. `revisions/REVIEW_0_5.md` assigns exact current owned paths and FP01–FP09 acceptance. The game designer owns pacing, story, choices and evidence-backed feedback; the interface engineer implements those interactions against the same model. Neither creates an alternative completion system. The clinic's first small loop is choose → power → connect → test → inspect the result → try a changed example.
